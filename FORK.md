## What changed vs upstream

### Behaviour (one function)

`VidriftStream/src/main/kotlin/com/sinemaku/vidriftstream/StreamEngine.kt`,
`resolveRealtime`: the VidRift server is launched immediately and gets a
2-second head start (`PRIORITY_HEAD_START_MS = 2000L`). The remaining farm
starts only if VidRift has produced nothing after that delay. If VidRift is
disabled in Settings or tripped by the circuit breaker, behaviour is
identical to stock IndStream (full fan-out). If VidRift fails or returns
nothing, the farm rescues the title exactly as stock IndStream would — the
fork never fails a title that stock IndStream would play.

The per-server attempt body was extracted unchanged into
`resolveServerAttempt` (+ a thin `resolveAndEmit` wrapper). Timeouts,
health tracking, dual TMDB/IMDB racing, subtitle handling and batch
emission are untouched.

## Build

Prerequisites: JDK 17 + Android SDK (compileSdk 36).

```sh
./gradlew :VidriftStream:make makePluginsJson
```

`make` triggers `shrinkCs3`, which repackages the plugin from the
R8-minified release classes. Output: `VidriftStream/build/VidriftStream.cs3`
plus `build/plugins.json` (generated by `makePluginsJson`).
Run the unit tests with `./gradlew :VidriftStream:testDebugUnitTest`
(`VidriftTest.vidrift_streams_pinnedConfig` pins the VidRift embed
format — if it fails, VidRift changed its page format).

On push to `main`, `.github/workflows/build.yml` builds and publishes
`VidriftStream.cs3` + `plugins.json` + `repo.json` to the `builds` branch
(reused unchanged from upstream — it globs `*.cs3`).

## Weekly upstream sync

Upstream moves fast (30 versions in 23 days at fork time) and
`StreamEngine.kt` changes weekly, so sync weekly — never let the fork
drift for months, or the `StreamEngine.kt` merge will conflict.

1. `git fetch upstream` (remote `upstream` = `https://github.com/dipender98/Indflix.git`)
   and check what changed (`git log --oneline HEAD..upstream/main`).
2. Merge or rebase the fork's commits onto the new upstream HEAD. The
   fork diff is small and isolated (one function + identity renames);
   rebase it, do not squash it into upstream commits.
3. If a merge conflict touches the head-start code, resolve it by hand:
   re-apply the head-start shape (priority partition → 2s delay → farm)
   onto the new upstream `resolveRealtime`. Never auto-resolve and never
   accept "ours/theirs" wholesale — read the upstream change first.
4. Run `./gradlew :VidriftStream:testDebugUnitTest`, then build
   (`./gradlew :VidriftStream:make makePluginsJson`) and verify the
   `.cs3` manifest (`pluginClassName`, `name`, `internalName`,
   `version`) before pushing.
5. Bump `version` in `VidriftStream/build.gradle.kts` by 1 for every
   published sync (the app uses `internalName` + `version` to detect
   updates). Push to `main`; the workflow publishes to `builds`.
